# 数字人纯文本显示与语音播报设计

## 目标

保证聊天框显示和数字人语音播报的 AI 回答均为自然纯文本。Markdown 控制字符、列表标记、代码围栏和 emoji 不得进入 ZEGO AI Agent 的最终输出。

## 根因

当前系统提示词只要求根据知识库友好回答，没有禁止 Markdown，千问会自然生成标题、加粗、列表和 emoji。前端使用 Vue 文本插值显示消息，因而会原样显示 Markdown。仅在前端渲染 Markdown 不能解决语音问题，因为 ZEGO TTS 接收的仍是模型原始文本。

## 选定方案

在后台设置两层保障：

1. 加强注册 AI Agent 时使用的系统提示词，要求回答简洁、口语化、适合直接播报，并明确禁止 Markdown、emoji、表格、代码块和装饰性列表符号。
2. 转发模型流式响应前，对每个 `delta.content` 做清理；去掉 Markdown 格式字符和 emoji，同时保留中文、英文、数字、正常标点及常见技术名称。

不修改知识库文档和检索结果，也不修改前端，因为聊天显示和数字人语音都会使用后台清理后的同一份内容。

## 组件

### 语音文本清理函数

新增一个独立的纯函数：

- 删除星号、标题标记和反引号；
- 删除位于行首的常见 Markdown 列表标记；
- 删除 emoji、变体选择符和零宽连接符；
- 保留正常换行与普通标点；
- 如果某个流式片段只有格式字符，安全返回空字符串。

### 流式代理

在序列化每个 OpenAI 兼容 SSE 数据块前，只清理 `choices[0].delta.content`。ID、结束原因、用量信息和最终 `[DONE]` 事件保持不变。

### 系统提示词

修改默认 ZEGO AI Agent 系统提示词，要求使用简短、适合语音播报的自然段。提示词负责主要风格控制，清理函数负责兜底保证。

## 数据流

`用户问题 → 百炼知识库检索 → 千问生成 → 逐个清理流式文本片段 → ZEGO AI Agent → 聊天显示与 TTS 播报`

## 异常处理

- 不存在 `choices` 或 `delta.content` 时原样透传。
- 内容不是字符串时原样透传。
- 只有格式符号的片段可变为空字符串，但不中断 SSE。
- 始终保留最终 `[DONE]` 事件。

## 测试

采用测试先行：

1. 先编写失败测试，复现加粗、标题、列表、代码围栏和 emoji。
2. 再验证普通中文、英文、数字、标点和技术名称不会被误删。
3. 实现后运行清理函数测试和 Next.js 生产构建。
4. Netlify 重新部署后，通过公司业务问题调用 `/api/chat/completions`，确认流式回答结束正常且不再包含 Markdown 或 emoji。

## 不在本次范围内

- 不重新构建知识库索引。
- 不在前端引入 Markdown 渲染器。
- 不修改检索排序和模型选择。
- 不在代码中强行截断回答，回答长度由系统提示词约束。
